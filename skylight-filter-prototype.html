Direction 1 — tradeoffs
✓ All filters in one place — no context switching
✓ Vessel detections fully visible without any Add/Remove step
✓ Lowest development lift from current state
✗ "8 more filters" label gives no hint of what's inside
✗ Total panel height is significant when expander is open
✗ Doesn't resolve conceptual tension between identifier lookup and map refinement
❓ Team question: do users filter by vessel name/MMSI to narrow a map view, or to find a specific vessel? The answer should drive this decision.

Direction 2 — tradeoffs
✓ Panel fits in one view without expanding — no hidden filters
✓ Cleaner conceptual split: "show me vessels like this" vs "find me this vessel"
✓ Search UI can surface auto-complete / recent vessels — richer than a text input
✗ Bigger change — requires rethinking the search bar scope and results
✗ Owner flag stays in the panel (it's a population filter, not an identifier lookup) — may feel inconsistent
✗ Users who currently filter by MMSI will need to learn a new location
❓ Team question: does the search bar apply as an AND filter with the panel filters, or does it open the vessel detail page? These are meaningfully different workflows and the answer changes the design.
